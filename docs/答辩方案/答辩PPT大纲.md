### **Part 2: 系统设计与实现 (建议4-5页)**

**Slide 4: 总体系统架构**
-   **标题：** 系统总体架构设计
-   **核心：** 阐述前后端分离的设计思想及其优势（解耦、并行开发、可扩展性）。
-   **视觉建议：**
    -   展示更新后的架构图，明确标注各模块的技术栈：**微信小程序 (Native) -> Python FastAPI (API Server) -> PostgreSQL (Database)**。
    -   清晰地标出数据流和通信协议（如HTTPS）。

**Slide 5: 前端技术方案与论证**
-   **标题：** 前端技术选型与合理性论证
-   **核心论点：** 为什么选择原生小程序框架？
-   **论证过程 (技术Trade-off分析):**
    -   **原生框架：** 性能最优、无抽象层开销、与微信生态集成度最高，符合工具类应用对流畅性的核心要求。
    -   **跨端框架 (Taro/Uni-app):** 存在性能损耗风险，对于此项目，原生开发的优势大于其开发成本。
-   **视觉建议：** 使用一个简明的技术对比表，从性能、生态集成、开发效率等维度进行分析。

**Slide 6: 小程序端详细设计**
-   **标题：** 小程序前端模块化与组件化设计
-   **代码架构：**
    -   **模块化 (`pages`):** 按功能划分页面，实现高内聚、低耦合。
    -   **组件化 (`components`):** 抽象可复用UI（如导航栏、卡片），提升开发效率。
    -   **工具库 (`utils`):** 统一封装API请求、数据格式化等，便于维护。
-   **视觉建议：** 展示代码目录结构截图，并对 `pages`, `components`, `utils` 三个核心目录进行高亮和文字说明。

**Slide 7: 核心功能实现与技术难点**
-   **标题：** 核心功能实现：从数据采集到可视化
-   **流程拆解：**
    1.  **图像采集：** 调用 `wx.chooseMedia`，并实现 **图像质量预检** 逻辑。
    2.  **数据传输：** 采用 `wx.uploadFile` 异步上传，并设置加载状态反馈。
    3.  **数据可视化：** 接收后端JSON，通过 **WXML与WXSS** 动态渲染为卡片式UI。
-   **技术难点与解决方案：**
    -   **难点：** 如何提升低质量图片上传后的识别成功率？
    -   **解决方案：** 在前端增加预览和裁剪提示，引导用户优化图片质量，经测试，后端识别成功率提升约30%。
